# Original History host START capture

Latest actual milestone: the original Steam History host now receives Gold's
authenticated acknowledgement **after Gold's actual native Ready readback**,
then activates the original enabled START widget. The genuine 21-byte original
event is copied and the producer's return to the same owned lobby is observed.
Original leave and application shutdown now complete with exit0/0 and strict
restoration in two independent bounded pairs with fresh session identities.
No native world event is sent or queued.
See the [actual ordered observations and limits](receipts/native-reverse-original-start-20261117.json).

The original Steam History host now has a separate, opt-in capture-only
primitive in `native/crossplay_history_start_hold.h`. It follows the existing
Gold hold contract. It does not add ordinary reverse-role admission, replay an
event or grant world permission. See the
[component and actual-pair receipt](receipts/native-history-start-capture-component-20261117.json).

The helper pins the complete original 208-byte START producer and owns only
its five-byte virtual-send callsite. Its entry replays the original sender load,
preserves the original continuation and five arguments, and returns with the
original 20-byte argument cleanup. The bridge preserves general registers,
flags, x87/SSE state and LastError. The borrowed original event must be copied
and validated synchronously before the original caller destroys it. The general
event sender remains unchanged.

Installation requires the actual admitted original Steam host/Gold guest
roster, owner thread, native preparation/cache/transport roots and matching
original methods. Capture additionally requires the same native session,
transport and cache, actual selected fresh map, empty save token and both native
human Ready bits. It permits only one attempt. Release restores only its exact
owned jump on the owning thread.

Original START UI actions can enqueue closed-slot changes before producing the
start event. Therefore capture does not assume that the earlier preparation
root or slot count survives that action unchanged. Complete neutral/AI setup,
fresh checkpoint/root equality and world permission remain the responsibility
of the existing later barriers. Capturing an event would not establish any of
those conditions.

## Earlier component verification and exclusion

The ten reverse component fixtures pass. The new component contributes 19
authored ABI/scope checks. Against the independently pinned original History
image, 29 compiled original-code guard cases, 29 exact owned-jump normalization
cases and two compiled continuation-entry cases pass. Those guard/entry checks
execute fixture code only, not original game code or a world.

Two actual original-game pairs installed the hold before Ready and repeated the
genuine native Ready exchange, standalone under DXVK 3.1.1 at normal pace.
Gold's already checked DLL and archive were reused exactly. Both clients exited0
in each pair, with strict guarded-file, profile, auxiliary-file and service
restoration. Neither pair recorded the original START UI action or a captured
start event. They do not qualify reverse world start, NEO or History-origin
save/reload. Each recorded one broker rejection whose exact cause was not
captured; it is not classified as a proven teardown-only rejection.

The second pair reused the existing original cached host-lobby refresh, but its
new exclusion reports exceeded the console command's existing 80-byte bound.
Absence of those reports does not identify the native or UI cause. Compact
reports now separately cover the original host page/role, native capture
availability and actual original widget conditions. The 80-byte limit remains
unchanged. All 568 candidate Lua members parse, unchanged archive payloads are
compared, and yielding/reentrant original refresh/START callbacks are checked
offline. The compact candidate has not run: the unchanged 7-GiB startup guard
excluded it before either game started. Guarded files were restored.

The prepared controller retains full asset hashes and the same RAM threshold
before deployment and immediately before launch. A bounded idle interval after
hashing can wait for that original buffer; file metadata and candidate hashes
are checked again afterward. No native lease or timeout is extended. That
historical START exclusion was subsequently identified and corrected below;
complete native setup/root/world integration remains separate work.

## Native identity and cleanup corrections

The compact diagnostic identified an empty remote human name in History's
preparation row2. Both native cache slots were Human and Ready; the original
preparation teams already differed. The unchanged original UI treats an empty
Human name as an Open slot. `crossplay_history_host_guest_identity.h` now reuses
the existing original History ID/name setters with the actually admitted remote
participant. It preserves every other byte of the complete preparation container,
including Ready, team, controller and castle. Its 39 authored ABI/storage/scope
checks and 23 compiled original-image integrity cases pass.

Capturing START exposed a separate teardown defect. Direct shutdown produced a
pure virtual call from a pending Storm session-update operation. Omitting the
old presence publication did not fix it and was rejected. Original leave, both
before and after retiring our observers, exposed the same null SDK-session
metadata access. These failed runs remain failed; they are not clean-start proof.

`crossplay_history_sdk_cleanup.h` is an explicitly armed cleanup primitive. The
caller first proves the captured original START interval and retires its own
preparation observers. The primitive binds the actual published SDK context,
owner thread and typed original host SDK session. This context is not treated
as a polymorphic object. It pins the complete original 335-byte metadata method,
30-byte wrapper and 10-byte context getter, and owns only the five-byte call.
Calls with an SDK session use the complete original method. In this one owned
cleanup epoch, a metadata update after that SDK session has disappeared is a
no-op; no Ready, checksum, clock, leave success or world result is supplied.

Each actual pair observed two such absent-session updates, the original
session-left condition, original shutdown and exit0/0. All four clients' guarded files,
profiles, auxiliary files and services were restored. The public primitive
canonically matches the tested code; 14 authored ABI/FP/stack/forwarding checks
and 11 original plus 11 exact owned-call integrity cases pass. All twelve public
reverse component fixtures pass 470 authored checks.

Gold's working SDK Ready source hold comes from its separately verified source.
Only the acknowledgement after actual original cache readback was added there;
History reuses its checked host binary. An earlier attempt to build Gold from
the older Gold portion of the History source was rejected before START and is
retained as a source-provenance regression, not passing evidence. The existing
Ready-state codec binds the acknowledgement to the peer, revision and exact
observed states; the host re-observes its native state within the same 10 s bound.

These components have no automatic activation in ordinary adapters. Reverse
world delivery, complete native setup/root agreement, active NEO logistics and
History-origin save/reload remain open. The next implementation must reuse the
existing guarded world pipeline after completing the missing native Gold guest
preparation and common setup barriers.
