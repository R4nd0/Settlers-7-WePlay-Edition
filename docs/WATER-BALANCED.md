game programs remain private recipient data; only authored recipes and hashes

B's reflection weight is `0.05 + 0.73(1−saturate(NdotV))⁵`, before the original
class multiplier. At cosine 0.5 this increases A's 0.04594 to 0.07281; normal
views regain some shine. Extreme grazing reflection is reduced, retaining a
controlled surface rather than restoring the original broad silver speckle.
The exact difference before the class multiplier is `0.03−0.10(1−cosine)⁵`.
There is no global colour grade, and depth, flow, texture, atmosphere, output,
alpha and anti-glitter specular instructions are byte-for-byte the same as A.

`water_variants.prepare(..., variant='A'|'B', ...)` requires an explicit fixed
choice and checks every original vendor alias before writing immutable files.
Each variant has its own recipe/hash path and receipts. It never repins A or
modifies a running case checkpoint. The native transport stays exactly 1076
bytes: selection is the exact program SHA, not an unchecked numeric mode.
The native variant field reports 1 for configured A and 2 for configured B;
enabled/requested remain separate. Unknown SHA or mismatched recipe/hash paths
must fail without changing the current shader configuration.

CPU fixtures verify emitted angle/depth equations, two-float-only modification,
unchanged broad specular/depth operations, explicit stage selection, immutable
A artifacts, source failures and unknown/mismatched identities. Microsoft
D3DDisassemble accepts all three generated B aliases. The private native draft
also passed the existing 4058 authored COM checks and a production-pin A→B→A
