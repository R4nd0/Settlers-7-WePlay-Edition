## Corrected profile semantics

An earlier reverse helper treated preparation row+0x18 as the admitted
participant's opaque identity. Original Gold serialization disproved that
interpretation: the field is the `ProfileName` catalogue reference. Gold's
original CBase exception identified its ID-manager writer and the original
`ProfileName` callsite. A routing/native participant scalar can be absent from
that catalogue. Older name/identity readback receipts did not establish this
field's semantics or qualify a playable world.

The naming helpers now use the original CString setters for the admitted
display name and preserve the catalogue field during their own operation.
Their consumption checks cover names, roster, castle and original consumer
returns. Original Confirmed consumers can subsequently modify profile fields;
an intermediate field is not presented as a resolved selection.

The actual History host had selected `Default` and `Profile4` before the peer
Confirmed consumer. That consumer replaced the guest reference with an invalid
participant scalar. The adapter captures the genuine selections and native
preparation interval beforehand, then restores those exact selections through
History's original ID setter after the original castle receipt. A different
valid intervening choice, unknown replacement scalar, changed native root or
expired10-second interval is rejected. Every other complete preparation byte
is preserved and the actual native catalogue names are read back.

After the original enabled START, the host sends its actual catalogue names in
a peer-bound preparation frame. Gold resolves those exact keys to existing,
unique entries in its own catalogue, invokes its pinned original profile setter
and acknowledges actual canonical readback. Numeric catalogue IDs are not
copied between engines. No registry entry or arbitrary profile is created.

`crossplay_profile_name_reference.h` provides bounded registry observation and
unique-name lookup. `crossplay_human_profile_selection.h` contains this scoped
two-human selection/frame/preservation component. It grants no native Ready,
start, clock, NEO or save permission.
