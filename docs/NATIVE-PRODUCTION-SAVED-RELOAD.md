# Original Gold / History saved-session port

The normal-adapter core now has a separate saved-session path. It derives its
checkpoint from the actual original Gold save selected in the owned portable
profile. A fresh lobby, launcher manifest or synthetic Ready result cannot
authorize a load. Ordinary mixed-entry and content approval gates remain closed.

## File, lobby and original loader

The host retains a read lease on the complete selected archive and hashes its
original world member and serialized NEO metadata. The receiver consumes the
original saved configuration, file request, information and file blocks through
the build-specific original factories and clone consumers. Both the transferred
stream and the original resident History stream must match the checkpoint hash.
The resident stream is hashed again at the original start queue boundary.

Saved Ready requests have their own checkpoint-bound namespace. Capture during
the original file consumer is deferred to the owner pump, outside its cache
lock. Gold consumes the original Ready request; the resulting original state is
observed and projected through History's original setters and consumers. The
enabled original host START action, prepared receipt and queued receipt remain
distinct requirements. Original Ready values and world checksums are preserved.

The original SessionStarted event can have an empty save-name field despite a
successfully admitted saved cache. The Lua callback now queries the authenticated
queued/started native context and passes the original numeric multiplayer save
slot to the original boot route. This invokes `StartMPSaveGame`, rather than
creating a fresh map. Missing context fails closed; solo and fresh starts retain
their existing arguments.

## Saved players and NEO

The new bounded read-only version-8 saved-player prefix parser follows the
original regular binary serializer, including node versions and collection
markers. It records the dynamic Random/Seed scalar without changing it. It
validates all 25 player records, including special inactive actors, before
deriving the two supported saved AI slots. Saved AI profile, difficulty and
peaceful flags come from the file, rather than defaults in a newly created
lobby. The running original Gold rows must match those saved values.

The parser was compared with the pinned original Gold row reader executing
headlessly on two real successive host saves. All 25 selected metadata rows and
the complete prefix boundary matched in each case. The tested original row-code
and Random/Seed-code regions also match the actual prepared Gold image. This
metadata check does not replace full-file integrity or the original game loader.

Saved NEO uses the existing strict restricted pickle/NEO2 decoder. The source
must agree on logic turn, replay turn, enabled choice, feature mask and digest.
Loading arms that saved ledger; recreated Lua states observe its actual native
restoration and never begin an empty fresh ledger. Original Gold request
postload policy and separately owned saved-world arithmetic scope apply before
the scheduler advances. They retain executable, object, generation and ABI
guards. No task-count, CRC, RNG, clock or Ready value is fabricated.

An actual second-generation save exposed an overfitted postload restriction:
the initial source contained request states 0, 1 and 6, but later saves also
contain other states. Both original History request-class predicates return
false without consulting that state. An independent headless original-code
comparison covers 108 state/request-kind cases across Gold and both History
images. The port follows that original class policy while still requiring every
deserialized source field, registry identity, generation, caller and owner to
match. It does not guess a larger state enum or rewrite saved task states.

An original host save takes its native NEO snapshot at the actual logic turn
before the original pickle/save routine writes the archive. A subsequent reload
derives a new checkpoint from that new file; it does not reuse its predecessor's
seed, turn, archive identity or ownership interval.

## Original world teardown

An original world can remain alive after the transport closes. Gold's native
Ready observer must still recognize its authenticated playing-buffer AI rows
while the engine tears down that world. Its read-only ownership query now
revalidates the same original session, roster, source AI, module and agreement
after channel failure, provided the original world had already reached its Lua
and native dispatch lifecycle. It supplies no replacement Ready result.

The event and NEO command scopes still require a connected channel and the
active runtime phase. Failure cannot authorize another start, turn, mutation or
NEO lifecycle command. Resetting the temporary participant event does not unbind
its pinned read-only original-engine view.

## Actual saved-world evidence, 2026-11-17

Two fresh-owner original-game pairs loaded the same real Gold save at logic
turn 800 / replay turn 801. Each received 3,006 original blocks containing the
complete 24,620,367-byte world stream, verified both the transferred digest and
the original resident History stream, and invoked the original saved-game loader
on both clients. The original host then saved again at logic turn 900 / replay
turn 901. Both new original archives passed world/archive integrity and strict
NEO metadata validation.

| Original guest | Common original CRCs | Common native NEO snapshots | CRC/NEO differences | Gold / History exit |
|---|---:|---:|---:|---|
| Steam History | 440 | 98 | 0 | 0 / 0 |
| Ubisoft History | 477 | 98 | 0 | 0 / 0 |

Both pairs ran standalone under DXVK 3.1.1 at the original 100-ms clock, without
x20. Actual original getters observed both easy AI players building and receiving
construction goods in both clients. Native FIFO comparisons were active after
restoration. Original EOT scalars matched in both transport directions. All
clients exited normally; guarded files, portable profiles, auxiliary files and
services were restored, without overwriting newer preexisting saves.

The expected channel failure after the deliberately closed guest is retained
in the evidence. There was no runtime failure before that planned close and no
native startup-guard stop. Earlier exit-failure experiments remain unsuccessful;
they are not counted as passing qualification.

See the [sanitized measured receipt](receipts/native-production-saved-reload-20261117.json).
This establishes the bounded saved-world/active-NEO/resave milestone for these
two original edition pairs. It does not open ordinary entry or content gates.

## Verification and limits

`native/build_crossplay_resume.ps1` runs 44,595 authored protocol, archive,
metadata, Ready and source-boundary checks and builds the fixed-address ownership
guard fixture. The guard fixture is built, not natively executed by that script.
The production handoff build and both adapter builds also pass. Lua verification
covers 31 mixed-interface tests, 17 mixed NEO lifecycle tests and four original
Ready-action tests. These are separate from actual original-game evidence.
The latest production handoff run excluded its modeled Gold local-observer and
start-hold fixtures because their Windows addresses were occupied; their separate
guard images were built. These exclusions are not counted as executed tests.

Runtime qualification is limited to the measured edition pair, map, saved
roster, NEO state, original pace and ownership direction. Feature mask 19 is the
shared FIFO/individual-intent port; it is not a claim that Gold contains all
History NEO5 pickup/distance corrections. Remote EasyTier transport, reverse
hosting, additional maps/rosters, nonempty saved individual-priority marks and
the final installed package require their own evidence. No diagnostic adapter,
catalog or archive pin is promoted by this source integration.
