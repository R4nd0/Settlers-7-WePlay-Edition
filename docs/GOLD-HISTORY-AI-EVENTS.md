# Gold/History: original AI-profile event delivery

The opt-in AI-profile codec has delivered two original Gold events through the
native factories of both History editions under DXVK. This establishes event
capture, authenticated transport, original factory cloning and subsequent CPU
slot-cache observation. It does **not** establish complete AI preparation
agreement or a four-player world.

The subsequent [native preparation and world-start milestone](GOLD-HISTORY-AI-PREPARATION.md)
adds those steps and records bounded four-player runs with both History editions.

The ordinary adapters and release packages do not include this laboratory path.
The earlier [transport and AI-preparation status](GOLD-HISTORY-EASYTIER-AI.md)
records the frontend and EasyTier infrastructure separately.

## Original event and ownership

`CChangeAIPlayerProfileIDEvent` has class `0x1056e082`, subtype 57 and two
additional original scalar fields: network slot and profile ID. Its original
visitor writes 17 bytes; the original factory adds the four-byte class tag.
All three editions produced identical visitor bytes and readback fields in the
bounded offline fixtures. The live codec uses the original factory, not a
replacement serializer.

The sender scalar is a routing connection ID. The Gold setter obtains it from
the original session's slot lookup; its linked-list fields correspond to the
verified participant snapshot. The authenticated receiver translates only that
source scalar into its own namespace. Slot, profile, event type and asynchronous
flag retain their original values.

`crossplay_ai_profile.h` admits slots 3 and 4, positive signed-range numeric
profiles, two ordered revisions and a dedicated purpose tag. Peer identities,
frame lengths and order are checked before projecting the source ID. The caller
still owns channel authentication and exact setup agreement.

`crossplay_ai_profile_codec.h` additionally requires the owned fresh Monhaim
lobby, two actual human members, their routing identities, actual Ready state,
four-slot cache layout, original map/save state and stable session/cache/array
ownership. It checks complete original event methods and the inherited visitor,
plus the existing stream/factory integrity guards. Mutex layouts are pinned
independently for each edition.

The decoder requires byte-exact original factory read/write roundtrip before
the original local sender clones the event. It releases only its own decoded
factory value. A CPU-cache observation after that clone is deliberately distinct
from profile/difficulty/peaceful agreement in the preparation data.

## Snapshot and asynchronous cache handling

AI preparation waits for the original host page to observe the human guest and
actual human readiness. After capturing both original AI events, the laboratory
adapter waits for an original Gold configuration snapshot containing both Ready
humans and both CPU slots. It forwards that unchanged native snapshot first.

History can receive the two bounded AI frames while that configuration is still
queued. Delivery waits for actual cache readiness, with stable ownership and a
five-second deadline. No Ready value, CPU value, acknowledgement or turn is
manufactured. Invalid context or ownership changes fail closed.

## Verification

Two separate automatic Gold/Steam and Gold/Ubisoft DXVK High runs each observed:

- Original Gold events for slots 3/4 and profiles 29/24.
- Two authenticated, ordered receives and two original History factory clones.
- Both History CPU slot states after original cloning.
- The fresh original configuration transfer and actual Ready-cache gate.
- Normal exit 0 for both clients and complete restoration of profiles, archives
  and adapters, without replacing a pre-existing save.

The complete Gold and Steam AI-method/vtable regions also matched their actual
loaded runtime bytes through read-only inspection of the owned test processes.
Steam's encrypted on-disk bytes are not executable visitor fixtures; the runtime
guard remains mandatory. Ubisoft's original method guards passed as part of its
live factory delivery.

Synthetic checks separately cover 227 framing/configuration cases, 72 rejected
method-byte mutations, 24 unreadable method regions and the compiled stdcall
boundary. Those method tests execute compiled guard code with a modeled
`VirtualQuery`, while original game bytes remain data. Nine native mutex ABI
checks use owned Windows critical sections. They are not multiplayer tests.

The native mutex fixture can run with `--locks-only`. Mapping a complete original
image at its preferred address is not portable across Windows address layouts;
the compiled guard mutation matrix therefore ran in the bounded CPU emulator.

Both game runs stopped at the retained closed-extra-slot preparation/checkpoint
barrier. A separate four-slot AI preparation agreement is required before the
world-start guard can admit this setup. Actual four-player gameplay, adapted
maps with NEO, mixed save/reload, effective x20 throughput and a game connection
through EasyTier remain unqualified.
